## Settled design you must not contradict (summary; details in spec-v1)

- Sigils: `!` event, `$` dynamic, `@` widget, `?` optional, bare = plain. Functor values nest inside plain aggregates. `&` references, `read`/`update` blocks are future work. `%` does not exist.
- Lifting: all operations and applications lift over `!`/`$` by the operands' sigils; dynamics+one event → event with dynamics read through a tag (old value); two events → error. `?` lifts at the plain layer (applicative Maybe); `match` on `?` is its eliminator.
- Numbers: `+ - * /` resolved by inference via three built-in traits (equality, ordering, numeric); literals polymorphic; suffixed spellings `+~` (Int) `+.` (Float) when inference can't decide; no user-defined traits yet.
- Occurrence = atomic transaction. Holds commit at the end. Tag law: a dynamic read at an event gives its value before the occurrence. Change law: derived dynamics are prompt. Glitch freedom. Equality of readings. Build is occurrence zero.
- Delayed edges = reads of a dynamic's behavior side (tag, `!Switch`'s hold of inner events, a hold's value side). Prompt graph must be acyclic. A cycle through a delayed edge is legal (P8 as a static check inside a widget block; runtime detection otherwise).
- A widget built mid-occurrence behaves as if built just before the occurrence's inputs: sees all of n; a `dyn` built in n over a dynamic that changed in n builds once with the new value; closures run at most once per occurrence.
- `dyn` returns an event firing in every build occurrence incl. the first; result goes to the caller; `!Switch` is non-prompt; `$Join` is prompt; `for` over sorted maps (keyed; arrays index-keyed, second class); consolidation by result kind.
- Widgets: a widget is a description (value, no identity); a node is what one bind builds (identity, path, owns holds, cyclic placeholders, slots, children, subscriptions); nodes are not values (only positions in the hierarchy); ownership tree = GC; building is the only doing; `@main` takes nothing; `@started` is a pure primitive (dyn over a constant) firing once in the build occurrence.
- Elements: values of an extensible variant (`type Element = choice ..`; `tag Gui.Button of Element:` with fields, `requests: !R`, `responds: R`, `state: S`, any subset). Fields are plain data fixed for the slot's life; a dynamic where a field goes lifts into a `dyn` → fresh slot per change (rebuilds get fresh paths). Identity: responses by path; state by element value (shared, deduped). Element list `$(Path ==> Slot)` is an ordinary dynamic. Routing: against the list as the occurrence opened. Unknown path = error. Diode: inputs cause list changes; list changes never cause inputs.
- Creation rule (verbatim, keep prominent): "Elements never fire in the occurrence they were created. Firing within the same occurrence implies they could have been pure functions. Instead, elements with request-like semantics take an input event and fire their output event in a different occurrence." State elements have a value in their creation occurrence (oracle). Types express unavailability (`Unavailable | Known`); never `Pending/Fetching`.
- Interception: `intercept: fn (@a, !(Path ==> Response), $(fn Element -> @$State)) -> @(a, $(Path ==> Slot))`. `type Slot = record: element: Element; !request: Request` (typed per tag inside a match arm). Down: responses by path, state via the supplier (a dynamic of a function from element to a *widget returning the state dynamic*, built in the interceptor's node at slot creation, once per distinct element value). Up: the interceptor makes elements with `@Element` or doesn't. Nothing reaches past an interceptor unless Prism code sends it. Forwarding is manual (`\e: @Element e`); every policy is ordinary code. An interceptor answers requests only in a later occurrence (via a `Defer` element from the World).
- World: outermost interceptor, host language, owns the loop, starts every occurrence. Run call: in = responses by path, pushes by element value, oracle `Element -> State` (snapshot as the occurrence opened: previous snapshot answers the oracle, diff is the pushes); out = element list, request firings per slot, result, error. Turn = occurrences before the World acts; `Defer` (request/response element, answered later in the same turn, at most once per slot per turn, deferring backwards = error). No phases. World obligations: only send to known paths, discard late results for gone slots, never answer in the request's occurrence, oracle synchronous & consistent, `Unsupported` responses for unknown request tags, unknown state tag = error at creation. World core = shared host library. GUI is not a World concept: one GUI vocabulary (draw primitives / focusable regions / windows as tags), spoken by many Worlds (software raster, GTK, HTML/web, a native Prism system speaking X11 over sockets); layout/hit-testing/focus/text editing are Prism interceptors. Exit is `Process.Exit(requests: !Code)`. Fs/Time/Net/Clock/Process components are general, not CLI.
- Errors: a program's own failures are values; cycles/overflow/protocol errors abort the occurrence (transaction rollback); construction-abort for cycles found during a rebuild; a World may offer an `Errors` stream element programs subscribe to; quarantine of a subtree as a further option. Reasoning about these is welcome; no status tracking.
- Conformance: Test World + script language (Expect/Send/Together/State/Push/Returns/Fired/Quiet/Requested/Errors steps); law tests; programs; differential test between implementations.
- Implementations: Rust is the serious one (runtime: single-threaded Rc/RefCell, transactional run call, Dynamic::join, keyed list widget, slots/paths, state supply by building the supplier widget, InterceptWidget; lang: lexer/layout/parser/resolver/elaboration → typed AST (every lift explicit, build-time vs occurrence-time marks, groups), closure conversion, lint pass, closure compiler to `IrWidget` implementing the runtime's dyn-compatible widget trait; typed-AST text form for goldens; worlds: world core, Test World, CLI World, GUI World). Haskell is an alternate: its own lexer/parser/elaborator, interprets the typed AST against Reflex at runtime (does NOT compile Prism to Haskell source), Test World + reflex-dom World; shared typed-AST text form and transcript format; differential testing. Parallelism: fork-join per height later; optimistic across occurrences; sharded runtimes; not now. Values representation, `&`, native backends: future work. No LLVM.
- Current Rust runtime facts (branch on-fire-repros, 38 tests): Arc/Mutex everywhere (to become Rc/RefCell); height-ordered action map; Spider-style catch-up; `PolymorphicWidget`; `dynamic_widget` rebuild at child index 0; no Dynamic::join; no elements/paths/interceptor; test backend reads behaviors directly (to be replaced by run call); values enum `AnyValue { Arc(dyn), U32, I32, Unit }`. Known loose ends: `trace` leaks, `unreachable!()` stubs, scheduling at usize::MAX edge, DWAction index 0, WidgetDelegate exposing live slots, `backend_data` unsettable.

## Clarifications every chapter must follow (resolved while writing)

- Binding a dynamic of widgets lifts to `dyn`: `!x <- @Button $label` means `dyn $label:` around the build, with the bound name being the `!Switch` of the dyn's event; for a state-returning element it is hold-of-dynamics plus `$Join`, with the first build's result as the hold's initial value. Say this once where lifting over `@` is introduced and use the shorthand freely afterwards.
- `for` consolidation is prompt: a key that appears in occurrence n is built in n and anything its block fires in n (only pure code like `@started` can) is in the consolidated event in n. The parent sees it; the new block does not see itself.
- `@Element e` for an `e` whose tag is not statically known (a catch-all arm) returns the generic `@(!Response, $State)` with the per-slot types checked at runtime; in a tag-specific arm the types are the tag's.
- Request firings from a slot torn down in the same occurrence are reported to the World with their path; the World performs them if it can and discards any response, since the slot is gone.
- Empty map literal is `{}`. Lambda with named arguments is `\|e| body`; the bare `\body` form uses `_`. Do not write `\e: body`.
- Unit-like responses (`Click`, `Tick`, `Eof`) are unit types: `type Click = click`, value `click`.
- The canonical cache idiom is a hold of dynamics joined with `$Join`, so there is no one-occurrence hiccup.
- A dynamic's change event is a value, obtained with the plain prelude function `!Updated: fn $a -> !a` (fires with the new value in every occurrence the dynamic changes; never at build). No widget is needed to get it. (`@started` remains the way to get a firing at build.)
- Derived dynamics and holds do not dedupe equal values: a hold set to the value it already has still changes, a derived dynamic recomputed to an equal value still changes, and a `dyn` over it rebuilds. `$Distinct` (prelude, needs equality) suppresses equal-valued changes when wanted.
- Chapter 1's conventions are the book's: `Gui.*` tags for the GUI vocabulary, `Gui.Button` responds `Click`, catch-all arms write `(!resp, ignore) <- @Element _.element`, file paths are `Text`, exit/args/env are process things, not CLI things: `Process.Exit` (`requests: !Code`), `Process.Args` (state), `Process.Env` (state); `Clock` is a bare tag; `Cli.*` is only `Cli.Stdin`, `Cli.Stdout`, `Cli.Stderr`, `Cli.Signals`; `Time.After` is `requests: !Nat, responds: Nat` (a token echoed back), `Gui.Focusable` has only a `name` field (hit-testing is in the library), `Process.Child` is spawned by request and keyed by id, and a child process is killed by the World's cancel-on-teardown obligation.
- Exit is `Process.Exit` with `requests: !Code`. Nothing happens because an element appears or a widget is dropped.

## Decisions adjudicated after the first batch (binding for every chapter; the lint pass applies them)

- Tags: `Gui.*` is the primitive vocabulary every GUI World speaks: `Gui.Window` (responds with pointer, key and resize events; one per window), `Gui.Scene` (presence: the draw list for a window, as data), `Gui.Focusable` (name only; focus is a library concept), `Gui.Metrics` (state: text measurement/fonts, answered synchronously), `Gui.Frames` (responds per frame if asked). `Ui.*` is the Prism GUI library's own tags (`Ui.Button`, `Ui.Label`, `Ui.TextInput`, `Ui.VBox`, …), handled by the library's interceptors; they reach a World only if that World accepts them (the Test World accepts every tag; a native-toolkit World may). The World does no geometry; the library hit-tests. Worked examples that show a button under the Test World use `Ui.Button` responding `Click`.
- Literals: integer-spelled literals are `Nat | Int` by inference, decimal-spelled are `Float`; `-1` is an `Int`; prefix `+` is numeric identity; `+?` converts `Int` to `?Nat`; a `Nat` is pinned by annotation; no suffixed `Nat` operators.
- Lifting: field access and indexing lift like application (`!!panes.!inbox` is fine); interpolating an event in a text literal lifts; a trailing lambda as the last argument absorbs the rest of the line; binding a widget application whose result is plain gives a `$` holding the first build's value.
- Equality and ordering: records have equality when all fields do and no ordering; tuples/arrays/primitives/text are ordered; element equality is tag plus plain fields, excluding any request event; derived dynamics and holds never dedupe equal values; `$Distinct` (equality bound) does.
- `for` and the static cycle check: consolidation is prompt; the only prompt edge from a collection's change to the consolidated event is what a new block fires at birth (`@started`, inner `dyn` events), which the compiler can see; `@ Delete on !started` as a row result is a compile error; the ordinary todo list is legal.
- Inline `:` is a plain token the parser interprets; `else` terminates an inline block; `Gui.*` lexes as name, `.`, `*`; no guards in `match`; no `else`-less `if`; top-level annotations required.
- Errors: one tag `Error` with fields `kind: ErrorKind` (a closed choice: `Cycle`, `Overflow`, `UnknownPath`, `UnsuppliedState`, `DeferBackwards`, `Component`, `Build`), `spans`, `occurrence`; the World offers `Errors` (responds: Error) as a stream element; an occurrence aborted inside a turn stops the rest of the turn and the World acts on what committed; quarantine is a `quarantine: [Path]` input the World may send on the next run call; a failed `dyn` build does not fire the `dyn`'s event and is reported through `Errors`; a cycle found at `!Switch` adoption aborts the switching occurrence; a World component crash is a `Component` error, never an `Unsupported` response; `Wrap.*` and `Checked.*` prelude functions for arithmetic; a recursion depth guard in the closure compiler.
- Worlds: the snapshot is held still across a turn (pushes enter only with the first occurrence); a failed turn drops its responses and re-queues its pushes; pushes for values nobody has asked about are recorded, not delivered; `World.Tags` is a core-provided state element listing accepted tags; `Fs.Watch` is a state element holding a modification stamp; `Process.Spawn` is a request and `Process.Child(id)` is state keyed by id, killed under the World's cancel-on-teardown obligation; missed `Time.Every` ticks are skipped; a `Defer` reborn by a `dyn` at the same tree position counts as the same `Defer` for the once-per-turn bound; a CLI run ends on `Process.Exit` or when nothing can cause another occurrence (stdin until end, signals, in-flight requests and timers keep it alive; args/env/clock/watch do not); `Cli.Stdout`/`Cli.Stderr` are `requests: !Text, responds: WriteFailed`; two `Process.Exit` firings in one turn: the first in occurrence-then-list order wins; `Time.After` is `requests: !Nat, responds: Nat`; the CLI World includes `Net`; a tokio World batches inputs and holds a repeated path for the next turn; `Fs.Contents`' oracle may read synchronously with a size cap beyond which it answers `Unavailable`; IME queries are World policy.
- Interception: a new child slot whose element value already has a live supplied widget joins it regardless of the current supplier dynamic; pure code firing at a path created in the same occurrence is an unknown-path error; `@Element _.element` inside a tag-specific arm has that tag's types; `Kind: fn Element -> Kind` is a prelude function (the tag table is known).
- Suite: steps `Unrequested pattern` and `ExpectTopNone` exist; `State` steps may precede the build and must for any state tag the program creates at build (no `default:` in tag declarations); transcripts spell paths canonically (`0/#1/0`, `[k]`, `s/n` for supplier-built slots); independent `Defer`s fired in one occurrence are answered together; `Returns` on an event result is a script error; the suite's VBox responds `ChildInput(path, response)`.
- Compiler/plan: the typed-AST text form is `name: sigil type [mark] group = expr @span` with `placeholder`/`close` lines; inferred type variables are named by first appearance, left to right, top to bottom; let-generalisation at `let` of a lambda only; the world core is its own milestone; `Dynamic::join` has a third law test (outer switches to an inner that does not change); a hand-written widget and a compiled one share a canonical node structure stated in the runtime chapter.

## Decisions adjudicated after the second batch (binding; the lint pass applies them)

- `@Element`'s results have no graph edge from its `requests` field: the creation rule is a compiler fact, so a `for` block may read an event derived from its own consolidated result through an element's response.
- Paths: only slots, `dyn` generations, `for` keys and intercept children take segments; a plain widget-function application makes a node but adds no segment, so a `@Button` whose body holds the `dyn` prints as `0/#0/0`. Supplier-built slots print `s/n/...` with the supplied widget's own segments after the prefix.
- Errors at the boundary: one type `RuntimeError { kind: ErrorKind, spans, occurrence, ... }`; a wrong-typed or duplicate response from the World is kind `Component`; runaway recursion is kind `Overflow`; `Outcome` has `errors: Vec<RuntimeError>` for contained build failures. Quarantine: the runtime remembers the owners it named in its last error and the World passes back the paths it wants quarantined.
- `Runtime` is `Send` by `unsafe impl` with the unique-ownership argument; it is `!Sync`.
- Naming: the boundary's plain value type is `Value`; the typed wrapper is `Typed<T>`. `IrWidget { program, block, captures, span }` with `Program { functions, blocks, tags, constants }`. The runtime's target API includes `hold_first`, n-ary `map_n` and n-ary `tag_map_n`. The typed-AST text form is as chapter 11 defines it; a binding whose root is a graph node is marked `[occ]`.
- `for` over a widget parameter whose body is not visible is treated conservatively as able to fire at birth. The elaborator records "can fire at birth" on each `for` node and the text form prints it; the Haskell evaluator uses one `coincidence` over the membership patch only when that flag is set (the single permitted use of `coincidence`).
- `type Kind = record: requests: Bool; responds: Bool; state: Bool`; `Kind: fn Element -> Kind`.
- Element construction spells the request field as `requests=` (`Cli.Stdout(requests=!line)`); it is excluded from equality.
- `Int` is 64-bit signed and `Nat` 64-bit unsigned.
- GUI vocabulary, final: tags `Gui.Window` (responds: pointer, key, resize), `Gui.Scene` (presence; its `draw` field is a plain list of `Draw.*` values: `Draw.Rect`, `Draw.Text`, `Draw.Image`, `Draw.Clip`), `Gui.Focusable` (name only), `Gui.Metrics` (state), `Gui.Frames` (responds `Frame(now: Instant)`). - Rollback in the Haskell implementation is by replay on a fresh local timeline; quarantine scripts are Rust-only and chapters 8 and 9 say so.
